Technique I · First Principles

Strip away the supermarket. Keep the comparison.

Near-term product is not a shopper app — it is a structured product DB: categories by consumer substitutability, traits, shelf price, and normalized price-per-unit. Fresh tomatoes are not dried tomatoes. Retailer taxonomies must bend to ours.

Fresh tomato
Migros · barquette 500g CHF 2.80 → CHF 5.60/kg
≠
Dried tomato
Different category · different unit logic Not interchangeable

The comparison-ready row — four primitives

01
Substitutability category

Would a shopper swap these for an everyday purchase? LLM-suited assignment; our taxonomy, not theirs.

02
Traits

Organic, premium, and more — Galaxus-like facets for queries that actually filter.

03
Shelf price

What you pay for the purchasable unit on the shelf — the human-facing number.

04
Normalized unit price

Price per weight/volume. Agents infer barquettes into grams. Category unit protocol optional.

Technique II · Reverse Brainstorming

How does this fail spectacularly?

Flip each failure. Tap a card to reveal the safeguard that survived the night. Security was explicitly left out of scope — everything else earned a countermeasure.

Failure

LLM cost kills the solo project

Per-product or per-catalog calls make the economics unviable.

click to flip →
Safeguard

Eval + cost/item metric

Token-cost-per-item as a first-class metric (E3). Explore supply strategies under the same harness — don’t preload the whole catalog.

Failure

Wrong substitutability groups

Poor categorization accuracy breaks every downstream comparison query.

click to flip →
Safeguard

Search, don’t dump

Agent queries existing categories (C2). Embedding neighbors put ~90% of likely members in context before assignment.

Failure

Duplicate categories spawn

Agent creates new instead of reusing — taxonomy fragments into chaos.

click to flip →
Safeguard

Hygiene + prefer-match

Periodic taxonomy-hygiene agent (M2) and post-bulk reconciliation (M5). Prefer match-existing stays viable (I7).

Failure

Confident hallucinations

Model invents attribute values with no unknown signal — comparisons lie.

click to flip →
Decision

evidence_span mandatory

Every trait ships value + verbatim source substring. Deterministic validator rejects uncited non-nulls. Unknown → DLQ.

Failure

Unit extraction drifts

Inconsistent conversions within a category — price-per-kg comparisons rot silently.

click to flip →
Safeguard

Gate + validators

Unit extraction gated against category standards. Deterministic post-validators (R6) on unit consistency.

Failure

Eval measures the wrong thing

Metrics look great; real comparisons remain meaningless.

click to flip →
Safeguard

Split evals + bakeoff

Separate assign / create / traits / units (E2). Same golden set for model + context strategy bakeoffs (E5).

Failure

Portfolio looks dated

Working code, yesterday’s agentic stack — showcase fails its own ambition.

click to flip →
Direction

Explore O1–O5 under eval

Tools, CLI, Code Mode, LangGraph, hybrid — all viable. Only pure prompt chains (O6) die. Bakeoff is the showcase.

Failure

Wrong build-vs-buy

Reinvent wheels, or miss tools that would have saved months.

click to flip →
Direction

CLI over MCP bloat

Tooling refs noted: CLI-like interfaces, MCP context-window cost, Cloudflare Code Mode — compare, don’t guess.

evidence_span

Adopted as law: every trait is a pair — value + verbatim source substring. Uncited non-null values are rejected. Hallucination control leans on the eval set in development; runtime unknown/defer remains open to invention.

Climax · Synthesis

The product is the row.
The pipeline is the means.

Comparison-ready rows are the deliverable. The agent pipeline is how we get there. Eval bakeoffs on orchestration and product supply are the portfolio showcase. Library authority-control is the metaphor that keeps taxonomy honest.
